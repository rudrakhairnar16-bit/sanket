# Ethics, Privacy & Accessibility Framework

## 1. Human-in-the-Loop

SANKET is assistive technology, not an autonomous decision-maker.

The system should support the clerk and citizen rather than make eligibility, legal or administrative decisions.

## 2. Uncertainty

A wrong sign can create a communication error.

Therefore the system should prefer:

> uncertainty + escalation

over:

> false certainty.

## 3. Data Minimization

Camera data should not be retained by default unless explicitly required for:
- consented dataset capture;
- debugging;
- evaluation.

## 4. Consent

Dataset collection should explain:
- what is captured;
- why it is captured;
- where it is stored;
- who can access it;
- how long it is retained;
- how it can be deleted.

## 5. Accessibility

The interface should not rely on:
- color alone;
- audio alone;
- tiny text;
- ambiguous icons.

Critical status should use text/icon combinations.

## 6. Deaf-community Involvement

Future field validation should involve:
- Deaf signers;
- ISL experts;
- interpreters;
- accessibility practitioners;
- government counter staff.

## 7. Bias

Recognition quality can vary with:
- signer;
- skin/background contrast;
- lighting;
- camera;
- hand orientation;
- device.

Therefore evaluation should explicitly test diversity.

## 8. Transparency

Users should know when they are seeing:
- AI recognition;
- a visual aid;
- an official reference asset;
- a placeholder;
- an interpreter escalation.

## 9. Governance

SANKET should maintain:
- dataset version;
- model version;
- asset provenance;
- calibration version;
- evaluation date;
- known limitations.
